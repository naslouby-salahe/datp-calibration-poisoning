## 1. Purpose
Define the CP2 manifest schema and the deterministic child-seed scheme so every run
is reproducible and provenance is auditable.

## 3. Scope
- **Manifest schema** (typed): provenance (E=1 enforced, E=5 rejected, CP2-generated
  within this repository, checkpoint/round, split semantics), reservoir sampling mode,
  locked `mu_flag_threshold`, and **every derived child seed**.
- **Seed scheme:** `numpy.random.SeedSequence([training_seed, poisoning_seed,
  client_id, scope_id])` → spawn child generators. **No integer seed addition.**
  Co-victims differ by `client_id` (independent streams by construction).
- Helper to record each derived seed into the manifest.

## 4. Non-goals
- No injector logic yet (Phase C).
- No nondeterministic defaults.

## 5. Scientific locks
SeedSequence child seeds only; clean vs poisoned differ only by the poisoning
intervention; `PYTHONHASHSEED=0`; seed Python/NumPy/PyTorch CPU+GPU as inherited.

## 6. Coding locks
Typed manifest model; centralized seed helper; no integer seed addition; no `Any`;
deterministic.

## 7. Implementation guidance
Add a `cp2` manifest model (pydantic) + a seed-derivation utility with full coverage
in tests (same inputs → identical child seeds).
